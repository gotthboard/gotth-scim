# v1 compatibility and support contract

`github.com/gotthboard/gotth-scim/pkg/scim` is the only supported Go
package. The module root is governance-only and is not a public API.

## Compatibility promise

Starting with `v1.0.0`, releases in major version 1 follow Semantic
Versioning:

- patch releases preserve source compatibility and correct defects;
- minor releases may add API or protocol capability but do not remove or
  incompatibly change an exported declaration; and
- an incompatible public API or documented behavior change requires a new
  major version.

`api/v1.0.0.txt` is the baseline generated by the pinned Go toolchain.
`make verify-api` rejects an unreviewed public declaration or public API
documentation change. The snapshot is evidence, not permission to break the
contract: compatible additions still require release notes and tests.

The v1.0.0 baseline requires Go 1.26.6 or newer. A change to the module's
minimum Go version is compatibility-relevant and must be called out in the
changelog. The repository verifies with exactly Go 1.26.6 so the baseline does
not drift with a newer documentation renderer.

## Protocol and configuration support

The supported RFC surface is the matrix in `docs/conformance.md`. The
following remain consumer-owned: TLS, authentication middleware, authorization,
durable storage, provisioning-scope policy, product identity/session behavior,
and deployment operations. `MemoryStore` remains an ephemeral reference
implementation, not a durability promise.

Configured request-work limits remain enforced. RFC 7644 section 3.4.2.4 is
part of the stable pagination contract: a negative `count` is interpreted as
zero for GET and POST searches, yielding an empty page while retaining the
accurate `totalResults`. Malformed integer values remain errors; positive
counts remain capped by `MaximumPageSize`; and the configured candidate bound
is still enforced even when the requested page is empty.

## Error compatibility

The exported sentinels `ErrNotFound`, `ErrConflict`,
`ErrPrecondition`, `ErrTombstoned`, and `ErrTooMany` retain their identity
for `errors.Is`. `ProtocolError` and `ErrorResponse` retain their exported
fields and JSON shape.

The HTTP server preserves these stable mappings:

| Condition | HTTP status | `scimType` |
| --- | ---: | --- |
| resource not found | 404 | empty |
| uniqueness conflict or tombstoned identity | 409 | `uniqueness` |
| failed conditional write | 412 | empty |
| search candidate bound exceeded | 413 | `tooLarge` |
| malformed GET query `count` value | 400 | `invalidValue` |
| malformed POST SearchRequest field | 400 | `invalidSyntax` |

Human-readable `detail` wording is safe diagnostic text, not a machine API;
consumers must branch on status, `scimType`, or exported sentinel identity.
Unknown storage failures remain redacted as HTTP 500 responses.

## Maintenance

Only the latest v1 patch release is supported after a successor is published.
Security and protocol-correctness fixes are backported when they can preserve
the v1 contract. This document makes no calendar-length maintenance promise.
